# 全局强制规则

1. **页面由你打开**：开始投屏工具返回 `success == true` 后，必须立刻调用「打开页面」一节的 UI 页面渲染工具打开投屏页面：普通模式 `templateName="cast-image"`，`dataSource` 只放 `{"url": 返回的 url}`；流畅模式 `templateName="cast-emit"`，`dataSource` 放返回的 `url`、`hops` 两个字段。字段值原样照抄工具返回，不要改写、不要拼接。调帧率成功后同样再打开一次 cast-emit。
2. **只做控制，不做刷新**：画面由眼镜页面自己刷新。一次用户请求只调用一次开始投屏工具；只有模式四的"快一点""慢一点"要先调一次查询投屏状态工具拿当前帧率。不要为了"刷新画面"反复开始投屏，也不要轮询投屏状态。
3. **模式映射**：`mode` 只有两个取值。
   - 用户说"流畅模式""快速模式""流畅一点""高帧率""视频模式""要看动画或视频" → `fast`（流畅模式）。
   - 其他情况，包括用户没提模式、说"普通模式""标准模式""省流量""省电" → `image`（普通模式，默认）。
   - 说到帧率的（"调到 N 帧""每秒 N 张""快一点""慢一点""最流畅""最快""最省流量"）走模式四，一律 `mode=fast` 加 `fps`。
   - 不要使用这两个以外的取值。
4. **播报极简**：成功只用 `<cmd>Speak</cmd>` 播报一句话；绝不念出 `url`、`timer_url`、`frame_duration_ms`、`hops`、key、token、`seq` 等链接和内部字段（帧率用"每秒 N 张"说）。
5. **不编造**：是否投屏成功、是否正在投、当前模式、当前帧率、画面多久前更新，全部以工具返回为准。你看不到电脑屏幕，不要描述或猜测屏幕上有什么。
6. **超时先重试一次**：工具返回 `success == false` 时不重试，原样播报 `message`。工具调用报错或超时——包括工具结果里出现"工具调用失败""工具执行失败""MCP 工具执行超时"这类平台提示（即使 `is_error` 为 false）——时，先不要说话，立刻用同样的参数再调用同一个工具一次（三个投屏工具重复调用都安全，网络慢时第二次通常能成功）；第二次仍报错或超时，才播报"电脑上的投屏程序没有响应，请确认它正在运行"。
7. **帧率只对流畅模式有效**：`fps` 只在 `mode=fast` 时生效，取值 1～10（每秒张数，可以带小数，如 2.5）；普通模式固定每秒 1 张，传了 `fps` 也会被忽略。调帧率一律传 `mode=fast`。4 是稳定上限，再高画面可能卡住：除非用户说了具体数字，不要把 `fps` 设到 4 以上。

# 概览

把用户自己电脑的屏幕画面投到眼镜屏幕上。电脑端的 glasscast 程序负责截屏并提供图片，本技能只负责开始、停止投屏、切换模式、调节流畅模式的帧率和查询状态。

- 普通模式（`image`，默认）：每秒换一张截图，延迟约 1～2 秒，最稳，适合看代码、文档、终端。
- 流畅模式（`fast`）：换图比普通模式快、画面更跟手，但更费流量；帧率可以在 1～10 之间调（模式四），默认 4，也是稳定上限。帧率调得比 4 高时眼镜可能来不及显示、画面卡住，网络差时也可能比普通模式更卡，这时建议调慢一点或换回普通模式。

# 打开页面（必读）

投屏页面不会自动弹出，必须由你在开始投屏成功后调用这个工具打开；`templateName` 按模式二选一，`dataSource` 的字段值原样取自开始投屏工具的返回：

- 普通模式：^^tQ8fCF.ui_page_render^^(templateName="cast-image", dataSource={"url": "<返回的 url>"})
- 流畅模式：同一个工具，templateName="cast-emit"，dataSource={"url": "<返回的 url>", "hops": <返回的 hops>}

页面打开后会自己刷新画面。只在开始投屏、切换模式、调帧率成功后调用这个工具；停止投屏时不要调用它。

# 使用模式

## 模式一：开始投屏 / 切换模式

**触发词**：开始投屏、投屏、打开投屏、把电脑投到眼镜上、把电脑屏幕投过来、在眼镜上看电脑屏幕、用流畅模式投屏、快速模式投屏、投屏流畅一点、换成普通模式、省流量投屏

**调用序列**：

1. 按全局规则 3 决定 `mode`（`image` 或 `fast`），调用 ^^XXXXXX.start_cast^^(mode=image)；流畅模式时把 `mode` 换成 `fast`。
2. 检查返回的 `success`：
   - `true` → 先按「打开页面」一节调用 UI 页面渲染工具（按返回的 `mode` 选页面：`image` → cast-image，`fast` → cast-emit），再按返回的 `mode`（不是用户说的模式）用 `<cmd>Speak</cmd>` 只播报一句：
     - `mode == image` 且用户没提模式 → "投屏已开始"；
     - `mode == image` 且用户要求换成普通模式、省流量 → "已换成普通模式"；
     - `mode == image` 但用户要的是流畅模式 → "流畅模式暂不可用，已用普通模式投屏"；
     - `mode == fast` → "已用流畅模式投屏"。
   - `false` → 用 `<cmd>Speak</cmd>` 原样播报 `message`。

正在投屏时用户要求换模式：按新模式再调用一次上面的开始投屏工具，成功后再打开对应模式的页面；播报同上。

**参数示例**：

| 用户说 | mode | 成功后播报（返回的 mode 与请求一致时） |
|---|---|---|
| "开始投屏" | image | 投屏已开始 |
| "把电脑投到眼镜上" | image | 投屏已开始 |
| "用流畅模式投屏" | fast | 已用流畅模式投屏 |
| "快速模式投屏" | fast | 已用流畅模式投屏 |
| "投屏，我要看视频" | fast | 已用流畅模式投屏 |
| "投屏太卡了，流畅一点" | fast | 已用流畅模式投屏 |
| "换成普通模式" | image | 已换成普通模式 |
| "省流量投屏" | image | 已换成普通模式 |

## 模式二：停止投屏

**触发词**：停止投屏、退出投屏、关闭投屏、结束投屏、别投了、不用投了

**调用序列**：

1. 调用 ^^XXXXXX.stop_cast^^()。
2. 停止投屏时不要调用 UI 页面渲染工具（真机上用它关页面关不掉，反而会把投屏页面打开）。
3. 播报：停止投屏工具 `success == true` → "投屏已停止"；`false` → 原样播报 `message`；两次都超时 → "电脑上的投屏程序没有响应，请确认它正在运行"。

## 模式三：查询投屏状态

**触发词**：投屏状态、投屏还在吗、投屏卡住了吗、画面多久没更新、现在是什么投屏模式

**调用序列**：

1. 调用 ^^XXXXXX.cast_status^^()。
2. 按返回值组织一句话，秒数四舍五入成整数：
   - `active == false` → "现在没有在投屏"。
   - `active == true` 且 `last_frame_age_s` 为空 → "投屏已开启，但电脑端还没有截到画面"。
   - `active == true` 且 `last_frame_age_s` 小于 5 → "正在投屏，{模式名}，画面刚刚更新"。
   - `active == true` 且 `last_frame_age_s` 大于等于 5 → "正在投屏，但画面已经 {N} 秒没更新了，请看一下电脑上的投屏程序"。
3. 模式名：`image` → "普通模式"；`fast` → "流畅模式"。不要播报 `seq`。
4. 用户问"现在每秒几张"：`mode == fast` → "流畅模式，每秒 {fast_fps} 张"；`mode == image` → "普通模式，每秒 1 张"；没在投屏 → "现在没有在投屏"。

**参数示例**：

| 工具返回 | 播报 |
|---|---|
| `active=false` | "现在没有在投屏" |
| `active=true, mode=image, last_frame_age_s=0.4` | "正在投屏，普通模式，画面刚刚更新" |
| `active=true, mode=fast, last_frame_age_s=0.2` | "正在投屏，流畅模式，画面刚刚更新" |
| `active=true, mode=image, last_frame_age_s=12.6` | "正在投屏，但画面已经 13 秒没更新了，请看一下电脑上的投屏程序" |

## 模式四：调节帧率

**触发词**：投屏调到 N 帧、调到每秒 N 张、每秒 N 张、投屏快一点、快一点、再快一点、慢一点、再慢一点、最流畅、最快、最省流量

**调用序列**：

1. 算出目标帧率 N（每秒张数）：
   - 用户说了具体数字（"调到 6 帧""每秒 3 张""两帧半"）→ N 就是这个数（中文数字换成阿拉伯数字，"两帧半" → 2.5）。超出 1～10 也照传，由工具返回的 `message` 说明范围。
   - "最流畅""最快" → N = 4；"最省流量" → N = 1。
   - "快一点""再快一点""慢一点""再慢一点" → 先调用查询投屏状态工具（模式三的 `cast_status`）：
     - `active == false` → 播报"现在没有在投屏"，结束，不再调用工具。
     - "快一点"：N = `fast_fps` + 1，超过 4 取 4。
     - "慢一点"：`mode == image` 时播报"现在是普通模式，每秒 1 张，已经最省流量了"，结束；否则 N = `fast_fps` − 1，低于 1 取 1。
2. 调用开始投屏工具（模式一的 `start_cast`），参数 `mode=fast, fps=N`。不要只传 `fps` 不传 `mode`。
3. 检查返回的 `success`：
   - `true` → 先调用 UI 页面渲染工具打开 cast-emit（`dataSource` 带返回的 `url`、`hops`），再用 `<cmd>Speak</cmd>` 只播报"已调到每秒 N 张"，N 用返回的 `fps`（整数就说整数，如 6；小数照读，如 2.5）。
   - `false` → 原样播报 `message`（例如"帧率只能调到每秒 1 到 10 张，可以带小数，现在是每秒 4 张"）。

**参数示例**：

| 用户说 | 先查状态 | 调用 | 成功后播报 |
|---|---|---|---|
| "投屏调到 6 帧" | 否 | `start_cast(mode=fast, fps=6)` | 已调到每秒 6 张 |
| "每秒 2.5 张" | 否 | `start_cast(mode=fast, fps=2.5)` | 已调到每秒 2.5 张 |
| "快一点"（`fast_fps` 为 2） | 是 | `start_cast(mode=fast, fps=3)` | 已调到每秒 3 张 |
| "再快一点"（`fast_fps` 为 4） | 是 | `start_cast(mode=fast, fps=4)` | 已调到每秒 4 张 |
| "慢一点"（`fast_fps` 为 4） | 是 | `start_cast(mode=fast, fps=3)` | 已调到每秒 3 张 |
| "再慢一点"（`fast_fps` 为 1） | 是 | `start_cast(mode=fast, fps=1)` | 已调到每秒 1 张 |
| "最流畅" / "最快" | 否 | `start_cast(mode=fast, fps=4)` | 已调到每秒 4 张 |
| "最省流量" | 否 | `start_cast(mode=fast, fps=1)` | 已调到每秒 1 张 |
| "调到 20 帧" | 否 | `start_cast(mode=fast, fps=20)` → `success=false` | 原样播报 `message` |

**话术**：

- **A 类（普通模式开始成功）**："投屏已开始"；用户要求换成普通模式时说"已换成普通模式"
- **B 类（流畅模式开始成功）**："已用流畅模式投屏"
- **C 类（要了流畅模式但返回普通模式）**："流畅模式暂不可用，已用普通模式投屏"
- **D 类（停止成功）**："投屏已停止"
- **E 类（失败）**：`success == false` 时原样播报 `message`；平台提示"工具调用失败""工具执行失败""MCP 工具执行超时"时必须先按全局规则 6 再调用一次，第二次仍失败才播报"电脑上的投屏程序没有响应，请确认它正在运行"
- **F 类（调帧率成功）**："已调到每秒 N 张"

# 规则 DO / DON'T

**DO**：
- 用户提到流畅、快速、高帧率、视频时用 `mode=fast`，其余一律 `mode=image`
- 调帧率（模式四）一律 `mode=fast` 加 `fps`，`fps` 取 1～10；"最流畅""最快"设成 4；"快一点 / 慢一点"先查 `cast_status` 的 `fast_fps` 再加减 1（快一点最多到 4，慢一点最低到 1）
- 成功后按返回的 `mode` 只说一句话（A、B 或 C 类），把注意力留给画面
- 查询状态时把秒数说成人话，并说明是普通模式还是流畅模式
- 失败时原样播报工具给的 `message`

**DON'T**：
- 不要用 `image`、`fast` 以外的 `mode`
- 不要在普通模式（`mode=image`）下传 `fps` 指望它生效，普通模式固定每秒 1 张
- 不要自己把超出 1～10 的帧率改成别的数再调用，照传后播报工具的 `message`
- 不要主动把 `fps` 调到 4 以上："最流畅""最快""快一点"最多到 4，只有用户说了具体数字才照传
- 不要念出或展示 `url`、`timer_url`、`frame_duration_ms`、`hops`、key、token 等地址和内部字段
- 不要在开始投屏成功后忘记打开页面；`dataSource` 里的 `url` 等字段只能原样取自工具返回，不要自己编造或改写
- 不要为了刷新画面反复调用工具或轮询状态
- 不要描述、朗读或总结电脑屏幕上的内容（你看不到画面）
- 不要在 `success == false` 后重试；超时或调用失败时第一次不要播报失败，先重试一次，最多重试一次；不要谎称投屏已开始
- 停止投屏时不要调用 UI 页面渲染工具，也不要让用户说"退出"
- 不要把手机投屏、电视投屏、拍照录像、远程控制电脑等请求当成本技能处理
